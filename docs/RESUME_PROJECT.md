# 简历项目描述

## 项目名称

统一大模型接入与对话管理平台（Unified LLM Platform）

## 简历精简版

基于 FastAPI、LiteLLM、PostgreSQL 和 Docker 构建多供应商大模型统一接入平台，接入通义千问、DeepSeek 等模型服务；设计统一模型注册与请求协议，实现 JWT 用户鉴权、多轮会话持久化、历史消息恢复和流式/非流式调用；使用 SQLAlchemy 与 Alembic 管理用户、会话、消息及模型调用记录，并实现 Token、延迟、成功率和错误信息统计面板。

## 可拆分为三条经历

- 设计 FastAPI + LiteLLM 模型网关，通过统一模型 ID、请求结构和错误结构屏蔽不同供应商接口差异，支持普通模式、推理模式及流式响应。
- 基于 JWT、SQLAlchemy、PostgreSQL 和 Alembic 实现用户系统与会话数据模型，完成用户级数据隔离、会话历史恢复及消息与模型调用记录关联。
- 开发浏览器端聊天与调用统计页面，展示模型供应商、输入/输出 Token、响应延迟、调用状态和失败原因，并编写一键启动、健康检查和敏感信息扫描脚本。

## 面试介绍结构

1. 项目动机：不同模型供应商接口、参数和返回结构不一致，需要统一接入层。
2. 核心方案：浏览器只调用 FastAPI；FastAPI 进行认证、模型解析和数据持久化；LiteLLM 负责上游路由。
3. 数据设计：用户、会话、消息、模型调用四张核心表；消息通过序号保证顺序，模型回答可关联调用记录。
4. 工程问题：端口冲突、VPN/代理影响、服务健康检查、JWT 失效、数据库迁移和前端缓存。
5. 当前结果：能够登录、切换模型、进行多轮对话、刷新后恢复历史，并查看个人调用统计。
6. 后续方向：增加自动化测试、限流、RBAC、成本核算、异步任务和线上部署。
